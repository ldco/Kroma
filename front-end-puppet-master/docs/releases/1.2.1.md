# Release 1.2.1

Date: 2026-02-21  
Type: Patch (`1.2.0 -> 1.2.1`)

## Versioning Decision

`1.2.1` is correct because this is a backward-compatible follow-up release that clarifies and hardens `1.2.0` contracts without introducing intentional API/schema breaking changes.

## Exact Change Ledger (Feature by Feature, Fix by Fix)

Every item below is written as: `Before -> After -> Upgrade impact`.

### 1. Header/Footer Width Key Clarification and Compatibility Alias

`CFG-101` Files: `app/puppet-master.config.ts`, `app/composables/useConfig.ts`, `app/components/organisms/TheHeader.vue`, `app/components/organisms/TheFooter.vue`  
Before: Width setting name `features.websiteChromeWidth` was ambiguous and looked like full page content width control.  
After: Canonical key is `features.headerFooterWidthMode` with legacy alias fallback from `features.websiteChromeWidth`.  
Upgrade impact: Existing projects continue to run with old key in `1.2.x`, but should migrate to canonical key before alias removal target (`1.4.0`).

### 2. Contained/Full Semantics Formalized

`CFG-102` File: `docs/reference/configuration.md`  
Before: Team interpretation of `contained` and `full` could drift, and relation to onepager/page content width was unclear.  
After: Exact semantics are documented with desktop/ultrawide examples and explicit separation from main content/scrollytelling width.  
Upgrade impact: No runtime break; configuration intent is now explicit and consistent across teams.

### 3. Onepager Global Timeline Contract Formalized

`SCR-101` Files: `docs/reference/configuration.md`, `tests/composables/useScrollytelling.test.ts`  
Before: Global timeline contract was implicit and lacked dedicated regression coverage.  
After: Documented global contract (`--pm-scroll-progress` is full-page `0 -> 1`) and added regression test to verify full-page progression.  
Upgrade impact: Prevents regressions where local scene logic could accidentally break onepager narrative continuity.

### 4. Full-Bleed Scene Wrapper Contract Guarded

`SCR-102` File: `tests/server/styles/style-system-contract.test.ts`  
Before: Standardized onepager scene wrapper behavior could regress without a dedicated contract check.  
After: Added style/renderer contract coverage for shared `scene-full-bleed` application and scene directive usage.  
Upgrade impact: Ensures teams do not need per-section manual wrapper duplication.

### 5. Admin Nav Alignment Contract Guarded

`NAV-101` Files: `tests/server/styles/style-system-contract.test.ts`, `app/assets/css/layout/admin-header.css`, `app/assets/css/skeleton/nav.css`  
Before: Horizontal vs vertical admin nav alignment expectations were not strongly enforced in regression checks.  
After: Contract checks enforce:
1. Horizontal mode nav cluster centered.
2. Vertical mode nav top-anchored with footer pinned to bottom.
Upgrade impact: Reduces UI drift risk across admin navigation modes.

### 6. Release Documentation Upgrade Clarity

`DOC-101` Files: `docs/releases/1.2.0.md`, `docs/architecture/1.2.0.md`, `docs/releases/README.md`  
Before: Follow-up feedback resolution was not packaged as a dedicated patch release for downstream teams.  
After: Added clear migration cookbook, compatibility matrix, and feedback-resolution mapping in release/architecture docs.  
Upgrade impact: Upgrade path is explicit for product teams consuming the framework.

## Upgrade Actions (Project Maintainers)

1. Pull framework update and install dependencies:
```bash
npm install
```

2. Rename legacy width key if still present:
```ts
features: {
  headerFooterWidthMode: 'contained' // or 'full'
}
```

3. If you still use:
```ts
features: {
  websiteChromeWidth: 'full'
}
```
replace it with `headerFooterWidthMode: 'full'` (legacy alias remains supported in `1.2.x` only).

4. Verify onepager contract in browser:
1. Global timeline progresses top-to-bottom (`--pm-scroll-progress`).
2. Scene effects remain additive (`--pm-scene-progress`).

5. Verify admin alignment in both modes:
1. Horizontal admin header nav centered.
2. Vertical sidebar nav top-anchored.

6. Run validation pipeline:
```bash
npm run lint
npm run test:run
npm run build
```

## Contract Changes to Be Aware Of

1. Canonical width config key is `features.headerFooterWidthMode`.
2. Legacy alias `features.websiteChromeWidth` is fallback-only in `1.2.x` and planned for removal in `1.4.0`.
3. Onepager global timeline contract is explicit and regression-tested.
4. Admin nav alignment contract is explicit and regression-tested.

## Breaking Changes

None intentional at API/schema level.
