# Release 1.3.0

Date: 2026-03-07
Type: Minor (`1.2.1 -> 1.3.0`)

## Overview

Release 1.3.0 focuses on **API contract hardening** and **security improvements**. This release establishes strict API response envelopes, enhances RBAC enforcement, and improves the overall security posture of the framework.

> **Note:** This release is superseded by **[1.3.1](./1.3.1.md)** which contains documentation corrections and empty-state envelope fixes. For new deployments, start with 1.3.1. Existing 1.3.0 deployments should review the [1.3.1 correction ledger](./1.3.1.md) for accuracy updates.

## Major Changes

### 1. Strict API Response Envelope (PM-RCV-002)

All API endpoints now return a standardized success envelope format:

```typescript
// Success response format
{
  success: true,
  data: { ... } // Actual response data nested under 'data' key
}
```

**Affected Endpoints:** 96+ API routes migrated to strict envelope format.

**Excluded Paths** (intentional, per contract):
- `/api/ws` - WebSocket protocol handler
- `/api/docs/openapi.json` - OpenAPI spec document
- `/api/docs/swagger` - Swagger UI HTML
- `/api/media/s3/*` - S3 proxy stream handler

**Migration Impact:**
- Existing API consumers must now access response data via `response.data` instead of top-level properties
- Client code using `apiFetch` composable is automatically handled (envelope unwrapped)
- Direct API consumers need to update response parsing

**Before:**
```typescript
const response = await $fetch('/api/portfolios')
// response = [{ id: 1, name: 'Portfolio 1' }, ...]
```

**After:**
```typescript
const response = await $fetch('/api/portfolios')
// response = { success: true, data: [{ id: 1, name: 'Portfolio 1' }, ...] }

// Or use apiFetch composable for automatic unwrapping:
const portfolios = await apiFetch('/api/portfolios')
// portfolios = [{ id: 1, name: 'Portfolio 1' }, ...]
```

### 2. Centralized RBAC Enforcement (PM-RCV-003)

Enhanced section-level RBAC for admin and privileged routes:

**Files:**
- `server/middleware/auth.ts` - Auth middleware with section-level enforcement
- `server/utils/admin-rbac.ts` - Centralized RBAC helpers

**Features:**
- Section-aware authorization for all `/api/admin/*` endpoints
- Route alias support (e.g., `/api/admin/stats` → `health` section)
- Content admin section grouping for unified permissions

**Security Impact:**
- Users with authenticated sessions now receive proper `403` responses on unauthorized paths
- UI should redirect before render for unauthorized `/admin/*` deep links

### 3. Secret Settings Storage (PM-RCV-004)

Encrypted storage for sensitive configuration values:

**Files:**
- `server/utils/secrets.ts` - Secret encryption/decryption utilities
- `server/utils/storage/s3-private-url.ts` - S3 visibility contract

**Storage Envelope:**
```
enc:v1:{ivHex}:{authTagHex}:{cipherHex}
```

**Security Features:**
- AES-256-GCM encryption
- PBKDF2 key derivation (100,000 iterations)
- Production fail-fast if `PM_SETTINGS_ENCRYPTION_KEY` not provided
- Development/test fallback with warning

**Environment Variables:**
```bash
# Required for production
PM_SETTINGS_ENCRYPTION_KEY=your-32-character-strong-key
```

### 4. S3 Visibility Contract (PM-RCV-005)

Signed proxy delivery for private S3 objects:

**Files:**
- `server/utils/storage/s3.ts` - Storage adapter with visibility awareness
- `server/utils/storage/s3-private-url.ts` - Signed URL helpers
- `server/api/media/s3/[...key].get.ts` - Proxy endpoint

**Visibility Modes:**
- `public` - Direct S3 URLs via `S3_PUBLIC_URL`
- `private` - Signed proxy URLs via `/api/media/s3/*`

**Environment Variables:**
```bash
S3_VISIBILITY=private  # or 'public'
S3_PUBLIC_URL=https://cdn.example.com  # Required for public mode
S3_PROXY_SIGNING_KEY=your-signing-key  # Optional for private mode (falls back to S3_SECRET_KEY)
```

## Breaking Changes

### API Response Format

All API responses now use the strict envelope format. Client code must be updated:

```typescript
// Old pattern (no longer works)
const { items, meta } = await $fetch('/api/admin/contacts')

// New pattern
const { data: { items, meta } } = await $fetch('/api/admin/contacts')
```

### RBAC Enforcement

Authenticated users may newly receive `403` on previously over-permissive paths. Update UI to:
1. Check section access before rendering admin pages
2. Redirect unauthorized deep links to appropriate landing pages

## Known Issues

1. **Audit Script False Positives:** 7 endpoints show "unknown" status in `audit-api-envelope.mjs` due to AST parsing limitations. These endpoints are compliant - the script cannot trace `return response` patterns where the object is built separately.

   Affected endpoints (all actually compliant):
   - `/api/blog/posts.get.ts`
   - `/api/faq/index.get.ts`
   - `/api/features/index.get.ts`
   - `/api/health.get.ts`
   - `/api/portfolios/index.get.ts`
   - `/api/team/index.get.ts`
   - `/api/testimonials/index.get.ts`

2. **Integration Test Timeouts:** Some e2e tests timeout during server startup in minimal environments. Run with increased timeout or skip e2e suite for quick validation.

## Security Notes

### Encryption Key Requirements

**Production deployments MUST set:**
```bash
PM_SETTINGS_ENCRYPTION_KEY=<strong-32-char-key>
```

Alternatively, `SETTINGS_ENCRYPTION_KEY` is also accepted (legacy alias).

Generate a secure key:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**Development fallback:** Uses hardcoded key with warning (never use in production).

### S3 Private Mode

When using `S3_VISIBILITY=private`:
- All S3 object URLs must use the signed proxy endpoint
- Direct S3 bucket URLs should not be exposed to clients
- Signing key: `S3_PROXY_SIGNING_KEY` (optional, falls back to `S3_SECRET_KEY`)

### Key Performance Optimizations

1. **ComputedRef unwrapping** - Fixed `isOnepager` truthy bug causing unnecessary MutationObservers
2. **Portfolio item limiting** - Per-portfolio limit (12 items) instead of global limit
3. **Image priority hints** - `fetchpriority="high"` and `loading="eager"` on hero images
4. **Lazy data fetching** - Below-fold sections use `lazy: true` in `useFetch`
5. **Scoped MutationObservers** - Target specific mount elements instead of `document.body`
6. **Google Fonts preload** - SSR preload link reduces FOUT
7. **CSS class-based object-fit** - Replaced inline styles with BEM classes
8. **i18n bundle optimization** - `fullInstall: false`, `dropMessageCompiler: true`
9. **PurgeCSS path fixes** - Correct Nuxt 4 app directory structure
10. **DevTools disabled in production** - Reduces bundle size
